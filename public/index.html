Game Design Specification · v0.3 · pre-playtest

Are You an Acktual Local?

A Nantucket exploration and knowledge game. Players spend one island day moving across a road network, answering location-bound questions at a difficulty they choose, and racing the last boat home. The table crowns a winner; each player also receives an island identity.

Players 2–6Length 24–46 min (simulated median)Weight light · 1.4/5Age 12+ / 14+ (compliance decision, §14)Prepared by Eduardo

Every balance number in this document comes from the Monte Carlo engine in §10 (the same code runs live on this page). Numbers are hypotheses to be confirmed by table playtests, not conclusions.

04

Board graph & movement

The board is a graph, not a track. Nodes are real places; edges are the island's roads, weighted by length. Dice are removed on purpose: roll-and-move gives the player no decision, and the luck it supplies is moved to the Almanac and Harbor Rounds, where it creates shared table moments instead of solitary ones.

FIG 4.1 · schematic, not to scale · solid = road (weight 1) · thick = long road (weight 2) · dashed = Wave shuttle · ◆ = Locals' Table space

Movement options

WalkUp to 1 road weight. Draw 2 encounter cards, keep 1. Best when a lens is full and you need to steer.
BikeUp to 2 road weight. Draw 1. Best for stamping new places and completing regions.
WaveFrom Steamboat Wharf directly to a terminal ('Sconset, Madaket, Surfside, Jetties) or back. Uses the whole move. Closed during a Nor'easter.
Over-sandWauwinet ↔ Great Point costs 2 and is closed while "Fog" is showing.

Tier declaration

Every region card carries three questions on the same subject: Visitor (1), Regular (2), Local (3). The active player declares a tier before the reader (player to the left) reads it aloud. A correct answer ticks that many boxes in the card's lens. The declaration is a self-assessment: players sort themselves by how well they believe they know this part of the island.

FIG 5.1 · expected stamps per question by knowledge level · p = 1/(1+e−7(s−d)), d = 0.12 / 0.38 / 0.62
computing…

Bold = the tier a correctly self-assessing player picks. The best tier changes as knowledge rises (Visitor → Regular at s≈0.33, Regular → Local at s≈0.67), so the declaration is a real decision for everyone, not just experts.

Question writing targets follow from the model: across the playtest population a Visitor-tier question should be answered correctly ~80–85% of the time, Regular ~45–55%, Local ~15–25% by visitors and ~65–85% by locals. Questions outside these bands get rewritten (§13).

07

Scoring ledgers

Two separate ledgers on one sheet. Island Score decides who wins the table. Knowledge decides who you are on the island. Separating them is what lets a visitor have a great game and still, honestly, be a Summer Person.

IslandScore = Σlens min(tickslens, 3)      // knowledge counts, but capped per lens
            + places_stamped              // +1 per new location
            + 4 × regions_completed          // any 3 of a region's 4 places
            + harbor_points               // +5 closest, +1 second
            + 2 × challenges_passed
            + 2 × made_last_boat

Knowledge   = Σlens tickslens                 // uncapped, trivia only
Breadth     = count(lens where ticks ≥ 3)     // 0–4
tie-break: higher Knowledge, then most Local Secrets

Identity resolution

Read top to bottom; the first row a player satisfies is their identity. Names use island vernacular so the result feels like belonging, not a grade. Final names need brand/tone sign-off: some island terms can read as affectionate or as a jab depending on who says them.

Rows: true knowledge level of simulated players. Columns: identity the rules assign. Diagonal = correct. Mistakes should only ever be one step.

Why breadth is a gate and not a bonus: a player who aces every History question but can't name a beach is a history buff, not a local. Requiring 3 of 4 lenses at 3+ ticks makes "Acktual Local" mean what the brand means by it.

Rules engine reference

The rules are also written as code. The rulebook, the simulator, and a remote digital playtest build all come from this one definition, so a rule change is made once and tested before it reaches a printed page.

// rules/types.ts
type Lens   = 'history' | 'culture' | 'nature' | 'local';
type Tier   = 1 | 2 | 3;
type Move   = { kind: 'walk' | 'bike'; path: NodeId[] } | { kind: 'wave'; to: NodeId };
type Phase  = 'round_start' | 'move' | 'draw' | 'declare' | 'resolve' | 'harbor' | 'last_boat' | 'scoring';

interface Passport {
  ticks: Record<Lens, number>;  stamped: Set<NodeId>;  regionsDone: Set<RegionId>;
  harbor: number;  challenges: number;  secrets: CardId[];  madeLastBoat: boolean;
}
interface GameState { round: number; rounds: number; phase: Phase; active: number;
  players: { token: TokenId; at: NodeId; passport: Passport }[];
  decks: Record<RegionId | 'harbor' | 'almanac', CardId[]>; almanac: CardId | null; }

// rules/reducer.ts  (pure: same input -> same output, so games are replayable from a log)
export function step(s: GameState, a: Action): GameState {
  switch (a.type) {
    case 'MOVE':    assertLegal(s, a.move, activeAlmanac(s));      // weight budget, fog, nor'easter
                    return arrive(s, a.move);                         // stamp + region check
    case 'DECLARE': return { ...s, phase: 'resolve', declared: a.tier };  // locked before reveal
    case 'RESOLVE': return a.correct ? tick(s, lensOf(s.drawn), s.declared) : advance(s);
    case 'HARBOR':  return awardClosest(s, a.guesses, [5, 1]);
    case 'BOAT':    return setBoat(s, a.player, a.board);             // forfeits final encounter
  }
}

export const islandScore = (p: Passport) =>
  sum(LENSES.map(l => Math.min(p.ticks[l], 3))) + p.stamped.size + 4 * p.regionsDone.size
  + p.harbor + 2 * p.challenges + (p.madeLastBoat ? 2 : 0);

export function identity(p: Passport): Identity {
  const k = sum(Object.values(p.ticks)), b = LENSES.filter(l => p.ticks[l] >= 3).length;
  return k >= 24 && b >= 3 ? 'ACKTUAL_LOCAL' : k >= 18 && b >= 2 ? 'YEAR_ROUNDER'
       : k >= 11 && b >= 1 ? 'WASH_ASHORE'   : k >= 6 ? 'SUMMER_PERSON' : 'DAY_TRIPPER';
}

Content can't be calibrated at the table alone. 480 questions × ~12 attempts each is ~5,800 attempts, about 145 four-player games. Instead: tables calibrate the system, and a remote survey (forms of 40 questions, ~30 respondents each, split between visitors and residents) calibrates the questions. Questions outside their tier band get rewritten or moved to a different tier.
// calibrate.ts — flag questions outside their tier's target band after n ≥ 12
const BAND = { 1: [0.70, 0.95], 2: [0.35, 0.65], 3: [0.10, 0.35] };  // visitor respondents
for (const q of questions) {
  const { n, correct } = stats[q.id];  if (n < 12) continue;
  const p = correct / n, [lo, hi] = BAND[q.tier];
  if (p < lo) flag(q, 'too hard', p); else if (p > hi) flag(q, 'too easy', p);
}

Pricing check

Wholesale to island shops (≈ 2.5× landed)≈ $31
MSRP (≈ 2× wholesale)≈ $60–65
Direct-to-consumer margin at $60≈ 79%

If the target MSRP is lower, the first levers are the box (magnetic → telescoping already applied) and tokens (wood → printed chipboard), not card count.

Material & brand notes

Plastic-free build (board-stock insert, wood tokens, FSC paper) fits an elevated coastal brand and avoids a "souvenir" read. Square box sits flat on a coffee table like a book. Palette: harbor slate, fog grey, beach sand, cedar, eel-grass green; one accent (signal red). Serif display face, generous margins, no clip art.

Compliance decision needed early. Under US CPSIA, products designed primarily for children 12 and under are "children's products" that require third-party testing and a Children's Product Certificate. Age-grading the game 14+ (general-use) changes the testing path and cost. This should be decided with a compliance lab before the RFQ, because it affects the box copy and vendor requirements.
